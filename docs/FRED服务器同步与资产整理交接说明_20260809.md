# FRED 服务器同步与资产整理交接说明

> 文档日期：2026-08-09
>
> 使用对象：在另一台实验服务器上接手 Grid_Mamba 的 Codex。
>
> 当前任务：同步已经完成整理的 Grid_Mamba 代码，在目标服务器上盘点、补充并整理 FRED 相关资产。

## 1. 任务背景

Grid_Mamba 的非 FRED 代码、实验资产结构、工具目录和清理审计已经在来源
服务器完成整理。GitHub `main` 使用已经完成净化并线性接续的项目历史：

```text
仓库：https://github.com/Jws032/Grid-Mamba
分支：main
历史范围：从 2024-10-18 的初始提交连续记录至当前整理版本
```

旧开发历史已经完成一次性净化并接入 GitHub `main`。提交中的代码、配置、
文档和演进关系得到保留，历史数据集、预测结果、checkpoint、缓存和编译产物
已被移除。项目后续只维护 GitHub，不再依赖或同步 Gitee 远程。

目标服务器已有可运行的 Grid_Mamba 环境，但不保证拥有来源服务器上的
EVUAV、EV-Flying、Runtime 结果、checkpoint 或其他大型实验资产。缺少这些
被 Git 忽略的本地资产属于预期状态，不应据此重新训练、重新生成或恢复已经
删除的旧目录。

本次只补充和整理 FRED 相关内容。除非用户另外明确授权，不继续清理非 FRED
代码，不修改论文项目，不重跑已经冻结的非 FRED 实验。

## 2. 两台服务器之间的同步边界

### 2.1 通过 Git 同步的内容

- 模型、数据读取和训练代码；
- FRED 配置；
- FRED 实验及 Runtime 入口；
- 实验注册表、校验清单和中文说明文档；
- 小型、明确需要版本控制的不可变元数据。

当前受 Git 管理的 FRED 文件包括：

```text
configs/evisseg_fred.yaml
configs/evisseg_fred_area1250.yaml
dataset/fred_segmentation.py
tools/experiments/fred/run_fred_ablation.py
tools/runtime/fred/eval_fred_event_count_adaptivity_runtime.py
tools/runtime/fred/run_fred_event_count_adaptivity_runtime.sh
```

GitHub 仓库为 Public。不要在后续提交中写入访问令牌、密码、私钥、服务器
凭据或其他不应公开的信息。

### 2.2 不通过普通 Git 同步的内容

`.gitignore` 忽略了整个 `experiments/runs/`，因此以下内容不会随 `git pull`
自动到达目标服务器：

- checkpoint；
- 训练和测试日志；
- 预测结果；
- Runtime 逐样本结果；
- 本地数据集；
- 其他大型实验产物。

不要擅自使用 `git add -f` 提交大型 FRED 资产。需要跨服务器补齐时，应使用
`rsync`、受控复制或其他独立传输方式，并在传输前后核对 SHA-256。

小型 Runtime 锁和注册表会随 Git 到达目标服务器，但锁中引用的数据集、
checkpoint 和正式 Runtime 实体不一定存在。锁文件存在不等于底层资产完整。

## 3. 已确定的整理规则

1. 论文已经完成，不修改论文正文、表格、曲线、图片和已报告数值。
2. `Acc` 指标名称和已有数值不修改。
3. 论文采用的 Runtime 数值按原记录保留，不重新解释或替换。
4. 同一个被确认的正式实验目录内部全部保留，包括配置、checkpoint、日志、
   测试结果、Runtime 结果和来源记录。
5. 完成迁移并验证后删除源位置，不保留兼容目录或重复软链接。
6. 不重新建立已经删除的 `save_model`、`outputs`、`analysis_outputs`、
   `archive_pending` 或 `mlruns` 兼容入口。
7. smoke、失败、重复和开发期资产只能在完成只读盘点、给出依据并获得用户
   明确确认后删除。
8. FRED 数据实体继续放在工作区级 `datasets/`，不迁入 `Grid_Mamba/dataset/`。
9. 新增整理文档使用中文；代码标识、命令和历史路径保持原文。
10. 禁止使用 `git reset --hard`、`git clean -fdx` 等可能误删被忽略实验资产的
    命令。

## 4. 分阶段执行要求

每个阶段结束后先向用户报告结果和下一阶段计划，得到确认后再继续。不要在
首次接手时直接迁移或删除 FRED 资产。

### 阶段 A：同步前保护目标服务器状态

只执行只读检查：

```bash
git status --short --branch
git branch --show-current
git log -1 --oneline
```

若目标服务器存在本地修改：

- 已跟踪的代码和配置改动应先放入临时备份分支或生成补丁；
- 被忽略的 FRED 实验资产应复制到仓库外的明确备份目录；
- 不要用普通 `git stash` 代替大型资产备份；
- 记录原始路径、文件数、目录大小和关键文件哈希。

历史净化会改变旧提交哈希。若目标服务器的旧工作目录仍停留在净化前提交，
不要在其中直接 `git pull` 或把旧分支合并回 GitHub `main`。完成本地修改和
实验资产保护后，应新建目录并从 GitHub clone：

```bash
git clone https://github.com/Jws032/Grid-Mamba.git
cd Grid-Mamba
git branch --show-current
git remote -v
```

Public 仓库可通过 HTTPS 无认证读取；需要从目标服务器向 GitHub 推送时，
再为该服务器单独配置 SSH 公钥，并把远程切换为
`git@github.com:Jws032/Grid-Mamba.git`。同步完成后应确认当前分支为 `main`，
确认本文档存在，并以 GitHub `main` 的最新提交和干净工作区作为代码基线。

### 阶段 B：环境和代码入口检查

目标服务器已有环境，因此首先验证现有环境，不重新安装或替换包。环境参考
见 `docs/环境依赖版本记录.md`，核心组合为：

```text
Python 3.9
PyTorch 2.2.0 + CUDA 11.8
mamba-ssm 2.2.0
causal-conv1d 1.4.0
spconv-cu118 2.3.8
_GLIBCXX_USE_CXX11_ABI=False
```

至少检查：

- Python 和核心包版本；
- `torch.cuda.is_available()`；
- GPU 型号、驱动和可用显存；
- FRED 数据集实际路径；
- `train`、`val`、`test` 分割是否可读取；
- FRED 实验入口和 Runtime Shell 入口的 `--help` 或语法检查。

不要在这个阶段把依赖缺失 EVUAV 或 EV-Flying 本地资产的测试失败解释为代码
回归。先区分纯代码测试与资产依赖测试，只验证目标服务器实际具备依赖的范围，
并把跳过项及缺失路径写入报告。

配置中的绝对数据路径可能只适用于原服务器。优先使用
`run_fred_ablation.py --data-root <目标服务器路径>` 覆盖路径，不要仅因服务器
目录不同就改写正式 YAML。

### 阶段 C：FRED 资产只读盘点

盘点范围至少包括：

```text
Grid_Mamba/experiments/runs/fred/
Grid_Mamba/save_model/ 中的 FRED 目录
Grid_Mamba/outputs/ 中的 FRED 目录
Grid_Mamba/analysis_outputs/ 中的 FRED 目录
工作区 outputs/runtime/fred_event_count_adaptivity_v1/
与 FRED 有关的 MLflow 或临时输出
```

即使部分路径不存在，也应明确记录为“不存在”，不要创建空的兼容目录。

对每个候选实验记录：

- 原始路径和目录大小；
- 实验名称、配置和随机种子；
- epoch 完成情况；
- `best_iou`、`best_loss`、训练状态 checkpoint 是否存在；
- `summary.json`、评测 CSV、预测文件和 Runtime 结果是否完整；
- 是否为 smoke、失败运行、恢复训练、重复副本或正式候选；
- 与其他目录的文件级或递归 SHA-256 对比；
- 是否被活动配置、工具或注册表引用。

阶段 C 的输出应是一份中文盘点报告和建议分类，不执行迁移或删除。

### 阶段 D：确认正式 FRED 版本

当前代码预期的规范候选路径为：

```text
experiments/runs/fred/
├── baseline/
│   ├── SC12_GS_G4_FINE_LOW_MID/
│   └── area1250_ev_flying_config_exact_full_eval/
└── ablation/
    └── FRED_SC12_GS_SCALED/
```

这些只是当前配置和工具指向的候选名称，不代表目标服务器上的同名目录已经
自动成为正式版本。必须根据实际 checkpoint、summary、日志和用户决定确认：

1. 哪些 baseline 是正式实验；
2. 是否保留 area1250 独立正式版本；
3. `FRED_SC12_GS_SCALED` 是否为最终消融结果；
4. 若存在 rerun，采用哪个版本；
5. 哪些 Runtime 变体是正式版本；
6. 哪些 smoke、失败和开发版本可以删除。

未经用户确认，不进入迁移和删除阶段。

### 阶段 E：迁移与源路径收口

获得确认后按“一次处理一个来源”执行：

1. 将正式实体迁入 `experiments/runs/fred/` 下的规范目录；
2. 更新活动配置、工具和注册表；
3. 对迁移前后文件执行数量、大小和 SHA-256 核对；
4. 验证训练、测试和 Runtime 入口使用规范路径；
5. 删除已经完成迁移的原位置；
6. 确认没有断裂软链接和重复实体；
7. 更新中文整理进展和迁移/删除审计。

不要为了“暂存”重新创建 `experiments/archive_pending/`。尚未决定的资产保留在
原位置并记录为待确认，避免混淆已完成和未完成的迁移。

## 5. FRED Runtime 的特殊边界

FRED 事件数自适应 Runtime 是工作区级多模型共享实验，当前注册为外部引用：

```text
../outputs/runtime/fred_event_count_adaptivity_v1
```

来源服务器上的共享目录包含 Grid_Mamba 的三个窗口结果：

```text
grid_mamba_w25/full/
grid_mamba_w50/full/
grid_mamba_w400/full/
```

同时包含其他模型、smoke、校准和开发期结果。目标服务器可能只拥有其中一部分。

默认处理原则：

- 共享多模型 Runtime 继续保留在工作区级目录，不复制一份完整实体到
  `Grid_Mamba/experiments/`；
- Grid_Mamba 注册表只记录经确认的正式 `full` 资产及哈希；
- 不因为目标服务器缺少其他模型结果而删除或重新运行 Grid_Mamba 结果；
- smoke、失败和旧调试变体在完成跨模型依赖检查后另行确认；
- 两个工作区公共工具
  `tools/fred_event_count_runtime_common.py` 和
  `tools/eval_grid_mamba_fred_event_count_runtime.py` 不属于 Grid_Mamba 仓库，
  运行前必须单独检查是否存在。

如果用户后续决定把 Grid_Mamba Runtime 完全收口到仓库内，应先提出独立迁移
方案，不在本轮默认执行。

## 6. 验证要求

迁移后至少完成以下验证：

1. FRED 数据集三个分割读取正常；
2. 正式 checkpoint 使用 `strict=True` 完整加载；
3. 保存配置与当前核心模型接口兼容；
4. 已有 summary 和评测结果可读取，指标名称与数值未被改写；
5. 独立 smoke 使用临时输出目录，验证后不作为正式资产保留；
6. W25、W50、W400 Runtime 分别完成 preflight；
7. FRED 和纯代码单元测试全部通过；非 FRED 资产依赖测试只在对应数据集和
   checkpoint 实际存在时执行，缺失项明确记录为跳过；
8. 注册表 YAML、TSV 和校验清单格式正确；
9. `git diff --check` 通过；
10. 目标服务器实际存在的 `experiments/` 资产范围内不存在断裂软链接。

除非用户明确要求，不重新运行正式训练、正式测试或正式 Runtime。已有正式
结果应以资产完整性和配置一致性验证为主。

## 7. 版本控制和回传

建议在目标服务器完成同步后新建独立分支：

```text
chore/fred-assets-20260809
```

提交中只包含：

- 必要的 FRED 代码和配置修正；
- 中文盘点、迁移和验证文档；
- 实验注册表、路径映射和校验清单；
- 适合普通 Git 管理的小型元数据。

大型实验资产继续由独立传输保存。若来源服务器缺少目标服务器上的 FRED
正式资产，应在整理完成后生成传输清单，至少包含相对路径、大小和 SHA-256，
再由用户决定是否以及何时回传。

提交前必须向用户报告：

- 实际迁移和删除范围；
- 正式 FRED 实验选择；
- 未解决的外部资产依赖；
- 验证结果；
- Git 将提交的文件边界；
- Git 不包含的本地大型资产边界。

## 8. 首次接手时应返回给用户的信息

目标服务器 Codex 完成阶段 A 至 C 后，应先返回以下摘要，不继续执行删除：

1. 当前 HEAD、分支和工作区状态；
2. 环境与 GPU 是否可用；
3. FRED 数据集路径和三个分割的可读性；
4. 找到的 FRED 实验目录、大小和完成状态；
5. 找到的 FRED Runtime 目录和正式候选；
6. 目标服务器缺少但代码或清单引用的资产；
7. 推荐的正式版本、迁移映射和删除候选；
8. 需要用户判断的问题。

在得到用户明确确认前，停留在只读盘点状态。
